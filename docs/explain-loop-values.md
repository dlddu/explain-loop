# Explain Loop 제품 가치 문서

> 이 문서는 explain-loop의 모든 문서(PRD, AC, 테스트)의 최우선 판단 기준이다.
> 어떤 기능이든 "이 기능이 아래 가치 중 무엇에 기여하는가?"로 존재 이유를 판단한다.

## 제품 소유자
- dlddu (요청자) — ※ 초안 작성 시 가정한 값. 다른 책임자가 있으면 교체한다.

## 제품 한 줄 정의
설명 행위에 쓰는 패턴을 관리하고, 설명마다 어떤 패턴을 왜 골랐는지와 상대가 얼마나 이해했는지를 기록해,
다음 설명이 더 잘 이해되도록 만드는 도구.

## 제품 가치

### V1: 이해로 끝나는 설명
- **유형**: 추상적
- **설명**: 설명의 성공은 "설명을 했다"가 아니라 "상대가 이해했다"로 판단한다.
  패턴을 몇 개 썼는지, 설명이 얼마나 길고 화려한지는 성공 기준이 아니다.
  모든 기능은 받는 사람의 이해에 기여하는지로 평가한다.

### V2: 쓸수록 나아지는 설명
- **유형**: 구체적
- **설명**: 이해도 피드백이 쌓일수록 같은 사용자에게 주는 설명의 이해 점수가 오른다.
  이 제품이 일반적인 "설명 잘하는 프롬프트"와 다른 지점이다.
- **측정**: 평가된 설명이 20건 이상인 사용자에 대해,
  최근 10건의 평균 이해 점수 ≥ 최초 10건의 평균 이해 점수 + 0.5 (5점 척도)
  - 임계값(20건, +0.5)은 초기 목표치이며 데이터가 쌓이면 조정한다.

### V3: 설명 방식의 근거가 남는다
- **유형**: 구체적
- **설명**: 모든 설명에 대해 "어떤 요청과 컨텍스트를 보고, 어떤 패턴을, 왜 골랐는지"를 사후에 재구성할 수 있다.
  근거는 학습(V2)의 원재료이고, 사용자가 설명 방식을 신뢰하거나 교정할 수 있는 근거이기도 하다.
- **측정**: 생성된 설명의 100%가 요청 기록·컨텍스트 기록·패턴 선택 근거와 연결되어 있다.

### V4: 진화하는 패턴 레퍼토리
- **유형**: 추상적
- **설명**: 설명 패턴은 고정된 목록이 아니다. 사용자는 코드를 고치지 않고 패턴을 추가·수정·폐기할 수 있고,
  패턴이 바뀐 뒤에도 과거 설명이 어떤 버전의 패턴을 썼는지 남는다.

### V5: 부담 없는 피드백
- **유형**: 구체적
- **설명**: 피드백이 귀찮으면 쌓이지 않고, 쌓이지 않으면 학습(V2)도 없다.
  이해도 입력은 설명을 받는 흐름을 끊지 않을 만큼 가벼워야 한다.
- **측정**:
  - 이해도 점수 입력은 1회 조작으로 끝난다 (코멘트·막힌 지점은 선택 사항).
  - 평가 가능한 설명 중 점수가 입력된 비율(응답률) ≥ 60% — 초기 목표치.

## 가치 간 관계

```
V1 이해로 끝나는 설명          ← 최상위 목적
 └─ V2 쓸수록 나아지는 설명     ← 목적에 다가가는 메커니즘(학습 루프)
     ├─ V3 근거가 남는다        ← 학습의 원재료 ①: 무엇을 왜 했나
     ├─ V5 부담 없는 피드백     ← 학습의 원재료 ②: 그래서 이해됐나
     └─ V4 진화하는 레퍼토리    ← 학습이 고를 수 있는 선택지의 폭
```

가치가 충돌할 때는 위쪽 가치를 우선한다. 예: 근거 기록(V3)을 늘리느라 설명 응답이 느려져
이해(V1)를 해친다면 근거의 상세도를 줄인다.
