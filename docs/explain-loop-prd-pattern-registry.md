# PRD-1: 설명 패턴 레지스트리

## 배경

설명에 쓰는 패턴은 서로 다른 층위가 섞여 있다. "수준 선택"은 *무엇을 어디까지* 설명할지 정하고,
"이야기화"는 *어떻게 풀어갈지* 정하고, "시퀀스 다이어그램"은 *어떤 형태로 보여줄지* 정한다.
층위를 구분하지 않으면 "시퀀스 다이어그램 vs 수준 선택" 같은 비교 불가능한 선택이 생기므로,
레지스트리는 패턴마다 **레이어**를 둔다.

| 레이어 | 질문 | 예 |
|--------|------|-----|
| `framing` 프레이밍 | 무엇을, 어디까지, 누구 입장에서? | 관점 선택, 수준 선택, 목표 설정, 배경 지식 파악 |
| `development` 전개 | 어떻게 풀어갈까? | 빗대기, 상황 기반 예시, 장단점 비교, 이야기화, 구조화된 목차 |
| `representation` 표현 | 어떤 형태로 보여줄까? | 시각화, 상태 변경의 흐름, ERD, 시퀀스 다이어그램 |

## 달성 가치
- **V4: 진화하는 패턴 레퍼토리** — 패턴을 코드 수정 없이 추가·수정·폐기한다.
- **V3: 설명 방식의 근거가 남는다** — 패턴을 버전으로 관리해, 과거 설명이 어떤 정의의 패턴을 썼는지 재구성할 수 있다.
- **V1: 이해로 끝나는 설명** — 패턴마다 "언제 쓰고 언제 피하는지"를 담아 선택의 질을 높인다.
- **V2: 쓸수록 나아지는 설명** — 패턴별 사용 성과를 레지스트리에서 보며 레퍼토리를 다듬는다.

## 패턴 모델 (참고)

| 필드 | 필수 | 설명 |
|------|------|------|
| `id` | ✅ | 영문 slug. 한 번 정하면 바꾸지 않는다 (예: `sequence-diagram`) |
| `name` | ✅ | 표시 이름 (예: 시퀀스 다이어그램) |
| `layer` | ✅ | `framing` / `development` / `representation` |
| `summary` | ✅ | 한 줄 설명 |
| `use_when` | ✅ | 이 패턴이 효과적인 상황 |
| `avoid_when` |  | 피해야 할 상황 |
| `how_to_apply` | ✅ | 적용 절차 (설명 생성 시 그대로 지침으로 쓰인다) |
| `example` |  | 짧은 적용 예 |
| `relations` |  | `requires` / `pairs_with` / `conflicts_with` / `specializes` → 다른 패턴 id |
| `status` | ✅ | `active` / `deprecated` |
| `version` | ✅ | 내용 수정 시 1씩 증가 |

## 초기 패턴 세트 (시드)

| 레이어 | id | 이름 | 한 줄 설명 | 관계 |
|--------|----|------|-----------|------|
| framing | `perspective` | 관점 선택 | 누구의 입장·어느 각도(사용자/구현자/운영자 등)에서 설명할지 정한다 | |
| framing | `level` | 수준 선택 | 추상도와 깊이를 상대의 수준에 맞춘다 | pairs_with `background-probe` |
| framing | `goal-setting` | 목표 설정 | 설명이 끝났을 때 상대가 할 수 있어야 할 것을 먼저 정한다 | |
| framing | `background-probe` | 배경 지식 파악 | 상대가 이미 아는 것과 모르는 것을 확인한다 | |
| development | `analogy` | 빗대기 | 상대가 이미 아는 것에 빗대어 새 개념을 설명한다 | requires `background-probe` |
| development | `situational-example` | 상황 기반 예시 | 상대가 겪을 법한 구체 상황 안에서 개념을 보여준다 | |
| development | `pros-cons` | 장단점 비교 | 대안들을 같은 기준으로 놓고 장단점을 비교한다 | |
| development | `storytelling` | 이야기화 | 인물·사건·갈등의 흐름으로 개념을 풀어낸다 | |
| development | `structured-toc` | 구조화된 목차 | 전체 지도를 먼저 보여주고 부분으로 들어간다 | |
| representation | `visualization` | 시각화 | 구조·관계·크기를 그림으로 보여준다 | |
| representation | `state-flow` | 상태 변경의 흐름 | 상태와 전이 조건을 순서대로 보여준다 | specializes `visualization` |
| representation | `erd` | ERD | 엔티티와 관계를 그린다 | specializes `visualization` |
| representation | `sequence-diagram` | 시퀀스 다이어그램 | 참여자 간 메시지 순서를 그린다 | specializes `visualization` |

> 결정 메모: 요청 원안의 "배경 지식 파악 및 빗대기"는 두 패턴으로 나눴다.
> 배경 지식 파악은 빗대기뿐 아니라 수준 선택·관점 선택에도 쓰이는 선행 단계이기 때문이다.
> 대신 `analogy requires background-probe` 관계로 둘을 묶었다.

## Acceptance Criteria

### AC1.1: 코드 수정 없이 패턴 추가
- **설명**: 필수 필드(`id`, `name`, `layer`, `summary`, `use_when`, `how_to_apply`)를 갖춘 패턴을
  코드 수정·재배포 없이 등록할 수 있고, 등록 즉시 다음 패턴 선택(PRD-3)의 후보에 포함된다.
- **달성 가치**: V4
- **검증 방법**: 새 패턴 등록 후 바로 이어지는 패턴 선택의 후보 목록에 해당 패턴이 나타나는지 확인

### AC1.2: 패턴 정의 검증
- **설명**: 다음 경우 등록·수정을 거부하고 사유를 알려준다 —
  필수 필드 누락, `id` 중복, 정의되지 않은 `layer`, 존재하지 않는 패턴을 가리키는 `relations`,
  자기 자신을 `requires` 하거나 `requires` 순환이 생기는 경우.
- **달성 가치**: V4
- **검증 방법**: 각 위반 유형별 잘못된 패턴을 등록 시도하여 거부와 사유 메시지 확인

### AC1.3: 수정 시 버전 보존
- **설명**: 패턴 내용을 수정하면 `version`이 1 증가하고 이전 버전 내용은 보존된다.
  과거 설명의 선택 기록은 당시 버전을 계속 가리키며, 그 버전의 내용을 조회할 수 있다.
- **달성 가치**: V4, V3
- **검증 방법**: v1으로 설명 생성 → 패턴 수정(v2) → 과거 설명의 선택 기록에서 v1 내용이 조회되는지 확인

### AC1.4: 삭제가 아닌 폐기
- **설명**: 패턴은 `deprecated`로 폐기한다. 폐기된 패턴은 새 선택 후보에서 제외되지만
  과거 기록에서는 계속 조회되고, 다시 `active`로 되돌릴 수 있다.
  한 번이라도 설명에 쓰인 패턴은 물리 삭제할 수 없다.
- **달성 가치**: V4, V3
- **검증 방법**: 사용 이력 있는 패턴 폐기 → 선택 후보 제외 확인 → 과거 기록 조회 확인 → 삭제 시도 거부 확인 → 재활성화 확인

### AC1.5: 성과와 함께 보는 패턴 목록
- **설명**: 패턴 목록을 레이어·상태·키워드로 필터링해 조회할 수 있고,
  각 패턴의 사용 횟수와 평균 이해 점수(PRD-4 집계, 데이터가 있을 때)가 함께 표시된다.
- **달성 가치**: V4, V2
- **검증 방법**: 점수 데이터가 있는 상태에서 레이어 필터 조회 결과의 사용 횟수·평균 점수가 원본 기록과 일치하는지 확인

### AC1.6: 시드 패턴 세트
- **설명**: 최초 설치 시 위 표의 시드 패턴 13개가 `active` 상태로 등록되어 있고,
  모두 AC1.2의 검증을 통과한다.
- **달성 가치**: V4, V1
- **검증 방법**: 빈 저장소에서 초기화 후 패턴 목록 조회 → 13개 존재 및 검증 통과 확인
