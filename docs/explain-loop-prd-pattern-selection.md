# PRD-3: 패턴 선택·근거 저장·설명 생성

## 배경

설명을 바로 생성하면 "어떤 패턴을 왜 썼는지"가 결과물 속에 녹아 사라진다.
이 PRD는 **선택 → 기록 → 생성**의 순서를 강제한다. 먼저 어떤 패턴을 쓸지 정하고 이유를 저장한 뒤,
그 선택을 지침으로 설명을 생성하고, 설명의 각 부분이 어느 패턴에서 나왔는지 표시한다.
이 연결이 있어야 이해도 점수(PRD-4)를 패턴에 귀속시켜 학습할 수 있다.

## 달성 가치
- **V3: 설명 방식의 근거가 남는다** — 선택한 패턴·버전·근거·탈락 후보를 설명보다 먼저 기록한다.
- **V1: 이해로 끝나는 설명** — 프레이밍을 먼저 정하고, 패턴 간 관계를 지켜 일관된 설명을 만든다.
- **V2: 쓸수록 나아지는 설명** — 설명 구간과 패턴을 연결해 점수를 패턴 단위로 학습할 수 있게 한다.
- **V4: 진화하는 패턴 레퍼토리** — 레지스트리의 현재 상태(활성·버전)를 그대로 따르고, 없는 패턴 요청을 등록으로 이어준다.

## 기록 모델 (참고)

**PatternSelection**
- `selection_id`, `request_id`, `created_at`
- `mode` — `exploit`(성과 기반) / `explore`(탐색, PRD-4 AC4.7) / `user_override`(사용자 지정) / `cold_start`(데이터 없음)
- `selected[]` — `pattern_id`, `version`, `order`, `role`(이 설명에서 맡는 역할), `rationale`, `evidence[]`
- `evidence[]` — 컨텍스트 항목 id, 학습자 스냅샷 항목, 점수 집계 등 근거가 가리키는 대상
- `rejected[]` — 고려했지만 고르지 않은 주요 후보의 `pattern_id`와 `reason`

**Explanation**
- `explanation_id`, `request_id`, `selection_id`, `generated_at`, `body`
- `segments[]` — 본문 구간(섹션·문단·다이어그램)별 `applied_patterns[]`

## Acceptance Criteria

### AC3.1: 선택이 생성보다 먼저
- **설명**: 패턴 선택 기록이 저장된 뒤에만 설명이 생성된다. 선택 기록(`selection_id`)과 연결되지 않은 설명은 저장되지 않는다.
- **달성 가치**: V3
- **검증 방법**: 선택 기록 저장을 실패하게 만든 상태에서 생성 시도 → 설명이 저장되지 않는지 확인. 정상 흐름에서 `selection.created_at < explanation.generated_at` 확인

### AC3.2: 증거가 있는 근거
- **설명**: 선택된 패턴마다 근거(`rationale`)가 있고, 근거는 최소 하나의 증거(컨텍스트 항목, 학습자 스냅샷 항목, 점수 집계)를 `evidence`로 참조한다.
  "일반적으로 효과적이라서"처럼 이번 요청과 무관한 근거만 있는 선택은 저장을 거부한다.
  예외: `cold_start` 모드에서는 "참고할 데이터 없음"을 명시하고 패턴의 `use_when`을 증거로 쓸 수 있다.
- **달성 가치**: V3, V1
- **검증 방법**: 저장된 모든 선택의 `selected[].evidence`가 비어 있지 않고, 가리키는 대상이 실제 존재하는지 확인. 증거 없는 근거 저장 시도 시 거부 확인

### AC3.3: 탈락 후보 기록
- **설명**: 고려했지만 고르지 않은 주요 후보가 있으면 최소 1개 이상 탈락 사유와 함께 기록된다.
  (예: "`storytelling` 제외 — 상대가 빠른 참조용 요약을 원함")
- **달성 가치**: V3, V2
- **검증 방법**: 여러 패턴이 `use_when`에 해당하는 요청에서 `rejected[]`에 사유가 있는 후보가 1개 이상인지 확인

### AC3.4: 프레이밍 먼저
- **설명**: 선택에는 기본적으로 `framing` 레이어 패턴이 1개 이상 포함된다(무엇을, 어디까지 설명할지 먼저 정한다).
  포함하지 않는 경우(예: 사용자가 "다이어그램만 줘"라고 함) 그 사유가 기록된다.
- **달성 가치**: V1
- **검증 방법**: 선택 기록들에서 `framing` 패턴이 없는 경우 모두 사유가 있는지 확인

### AC3.5: 활성 패턴과 버전 고정
- **설명**: `active` 상태의 패턴만 선택되며, 선택 시점의 `version`이 함께 기록된다.
- **달성 가치**: V3, V4
- **검증 방법**: 폐기 패턴이 `use_when`에 정확히 맞는 요청에서도 선택되지 않는지, 선택 기록의 버전이 당시 레지스트리 버전과 같은지 확인

### AC3.6: 패턴 관계 준수
- **설명**: `requires` 관계의 패턴이 선택되면 선행 패턴도 함께 선택되거나, 생략 사유가 기록된다
  (예: `analogy` 선택, `background-probe` 생략 — "학습자 스냅샷에 배경 지식이 이미 있음").
  `conflicts_with` 관계의 두 패턴은 함께 선택되지 않는다.
- **달성 가치**: V1
- **검증 방법**: `analogy`가 선택된 기록에서 `background-probe` 포함 또는 생략 사유 확인. 충돌 관계 패턴 동시 선택 시도 시 거부 확인

### AC3.7: 패턴이 추적되는 설명
- **설명**: 생성된 설명의 각 구간(`segments`)이 어떤 선택 패턴을 적용한 것인지 표시된다.
  선택됐지만 본문에 적용되지 않은 패턴이 있으면 "미적용"으로 표시된다.
- **달성 가치**: V3, V2
- **검증 방법**: 생성된 설명에서 모든 선택 패턴이 하나 이상의 구간에 매핑되었거나 "미적용" 표시가 있는지, 매핑되지 않은 구간 패턴이 선택 목록 밖에서 오지 않았는지 확인

### AC3.8: 사용자 지정 패턴 우선
- **설명**: 사용자가 특정 패턴을 요구하면("시퀀스 다이어그램으로 설명해줘") 그 패턴이 반드시 포함되고,
  `mode: user_override`와 함께 근거에 사용자 요청이 증거로 기록된다.
  요구한 패턴이 레지스트리에 없으면 그 사실을 알리고 새 패턴 등록(PRD-1 AC1.1)을 제안한다.
- **달성 가치**: V1, V4
- **검증 방법**: 등록된 패턴 지정 요청 → 포함·모드·근거 확인. 미등록 패턴 지정 요청 → 안내와 등록 제안 확인
