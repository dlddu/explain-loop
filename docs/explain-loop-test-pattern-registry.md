# 테스트 문서 T1: 설명 패턴 레지스트리

## 검증 대상 AC
- AC1.1: 코드 수정 없이 패턴 추가 (PRD-1)
- AC1.2: 패턴 정의 검증 (PRD-1)
- AC1.3: 수정 시 버전 보존 (PRD-1)
- AC1.4: 삭제가 아닌 폐기 (PRD-1)
- AC1.5: 성과와 함께 보는 패턴 목록 (PRD-1)
- AC1.6: 시드 패턴 세트 (PRD-1)

## 테스트 시나리오

### T1-S1: 시드 세트 초기화
- **사전 조건**: 빈 저장소
- **실행 단계**: 1) 초기화 실행 2) 전체 패턴 목록 조회 3) 각 패턴에 정의 검증 실행
- **기대 결과**: 13개 패턴이 `active`로 존재하고(framing 4, development 5, representation 4), 모두 검증 통과
- **검증 AC**: AC1.6

### T1-S2: 새 패턴 추가 후 즉시 후보 포함
- **사전 조건**: 시드 세트 초기화 완료, 서비스 실행 중
- **실행 단계**: 1) 서비스 재시작 없이 `socratic-questioning`(development, 질문으로 스스로 답에 이르게 함) 등록
  2) `use_when`에 맞는 요청("내가 직접 생각해보면서 이해하고 싶어")으로 패턴 선택 실행
- **기대 결과**: 등록 성공, 선택 단계의 후보 목록에 `socratic-questioning`이 포함됨
- **검증 AC**: AC1.1

### T1-S3: 잘못된 패턴 정의 거부
- **사전 조건**: 시드 세트 초기화 완료
- **실행 단계**: 다음 각각을 등록 시도
  1) `how_to_apply` 누락 2) 기존 id `erd` 재사용 3) `layer: format`
  4) `requires: not-exist` 5) `requires`에 자기 자신 6) A requires B, B requires A
- **기대 결과**: 6건 모두 거부되고, 각각 위반 유형을 명시한 사유가 반환됨
- **검증 AC**: AC1.2

### T1-S4: 수정 후 과거 버전 조회
- **사전 조건**: `analogy` v1 상태
- **실행 단계**: 1) `analogy`를 써서 설명 E1 생성 2) `analogy`의 `how_to_apply` 수정
  3) 레지스트리에서 `analogy` 조회 4) E1의 선택 기록에서 `analogy` 내용 조회
- **기대 결과**: 레지스트리는 v2, E1의 선택 기록은 v1을 가리키고 v1 내용이 그대로 조회됨
- **검증 AC**: AC1.3

### T1-S5: 폐기·삭제 거부·재활성화
- **사전 조건**: `storytelling`이 설명 1건 이상에 사용됨
- **실행 단계**: 1) `storytelling` 폐기 2) `use_when`에 정확히 맞는 요청으로 선택 실행
  3) 과거 설명의 선택 기록 조회 4) `storytelling` 물리 삭제 시도 5) `active`로 재활성화 후 선택 실행
- **기대 결과**: 2) 후보에서 제외 3) 과거 기록에서 조회됨 4) 삭제 거부(사용 이력 사유) 5) 다시 후보에 포함
- **검증 AC**: AC1.4

### T1-S6: 성과 포함 목록 조회
- **사전 조건**: `representation` 패턴들에 대한 점수 기록 존재 (예: `erd` 4회 사용, 점수 4·4·3·5)
- **실행 단계**: 1) `layer=representation` 필터로 목록 조회 2) `status=deprecated` 필터 조회 3) 키워드 "다이어그램" 검색
- **기대 결과**: 1) 4개 패턴 표시, `erd` 사용 횟수 4·평균 4.0 2) 폐기 패턴만 표시 3) `sequence-diagram` 등 해당 패턴 표시. 점수 없는 패턴은 "데이터 없음"
- **검증 AC**: AC1.5
