# PRD-2: 설명 요청·컨텍스트 수집

## 배경

같은 질문이라도 누가, 어떤 맥락에서, 무엇을 이미 아는 상태로 물었는지에 따라 좋은 설명이 달라진다.
그리고 나중에 "이 설명이 왜 잘 통했나/안 통했나"를 학습하려면 **설명 당시의 입력**이 그대로 남아 있어야 한다.
이 PRD는 설명을 만들기 전에 요청과 컨텍스트를 수집해 저장하는 부분을 다룬다.

## 달성 가치
- **V3: 설명 방식의 근거가 남는다** — 패턴 선택 근거가 참조할 입력(요청·컨텍스트·학습자 상태)을 기록한다.
- **V2: 쓸수록 나아지는 설명** — "어떤 상황에서 어떤 패턴이 통했나"를 분석할 재료를 남긴다.
- **V1: 이해로 끝나는 설명** — 상대의 배경 지식을 축적해 상대에게 맞는 설명을 가능하게 한다.

## 기록 모델 (참고)

**ExplanationRequest** — 설명 요청 1건
- `request_id`, `learner_id`, `requested_at`
- `raw_text` — 요청 원문 (가공하지 않음)
- `topic` — 정규화한 주제 (예: "OAuth 인가 코드 흐름")
- `intent` — 상대가 이해하고 싶은 것·목적 (추출 가능할 때)
- `context_items[]`, `learner_snapshot`

**ContextItem** — 설명에 참고하려고 모은 자료 1건
- `kind` — `conversation` / `document` / `code` / `user_statement` / `prior_explanation` 등
- `source` — 출처 위치 (대화 턴, 파일 경로, URL 등)
- `excerpt` — 내용 또는 발췌
- `collected_at`, `used` — 실제로 쓰였는지 (생성 완료 시 기록)

**LearnerSnapshot** — 요청 시점의 학습자 상태 (복사본)
- 알려진 배경 지식, 명시적 선호·비선호 패턴, 패턴별 이해 점수 집계(PRD-4)

## Acceptance Criteria

### AC2.1: 요청 원문 보존
- **설명**: 설명 생성이 시작되기 전에 요청이 고유 `request_id`로 저장되며, 원문(`raw_text`)은 가공 없이 보존된다.
  정규화한 주제(`topic`)는 원문과 별도 필드로 저장된다.
- **달성 가치**: V3
- **검증 방법**: 요청 처리 직후 저장소에서 `request_id`로 조회해 원문이 입력과 바이트 단위로 같은지, `topic`이 별도로 있는지 확인

### AC2.2: 컨텍스트 출처 기록
- **설명**: 수집된 모든 컨텍스트 항목에 `kind`, `source`, `collected_at`이 기록된다.
  출처를 알 수 없는 항목은 `source: unknown`으로 명시되며, 빈 값으로 남지 않는다.
- **달성 가치**: V3
- **검증 방법**: 대화·파일·사용자 발언이 섞인 요청 처리 후 모든 항목의 세 필드가 채워졌는지 확인

### AC2.3: 학습자 스냅샷 고정
- **설명**: 요청 시점의 학습자 상태가 스냅샷(복사본)으로 요청과 함께 저장된다.
  이후 학습자 프로필이 바뀌어도 과거 요청의 스냅샷은 변하지 않는다.
- **달성 가치**: V3, V2
- **검증 방법**: 요청 A 처리 → 학습자 배경 지식 수정 → 요청 A의 스냅샷이 수정 전 값인지 확인

### AC2.4: 사용된 컨텍스트 표시
- **설명**: 설명 생성이 끝나면 각 컨텍스트 항목에 패턴 선택이나 설명 본문에 실제로 쓰였는지(`used`)가 기록된다.
  모으기만 하고 쓰지 않은 컨텍스트와 실제 근거가 된 컨텍스트를 구분할 수 있다.
- **달성 가치**: V3, V2
- **검증 방법**: 패턴 선택 근거(PRD-3 AC3.2)가 참조한 항목은 `used: true`, 참조하지 않은 항목은 `false`인지 확인

### AC2.5: 배경 지식 축적
- **설명**: 학습자가 스스로 밝힌 배경 지식(예: "백엔드 개발자야", "SQL은 알아")은
  `user_statement` 컨텍스트로 수집되고, 학습자 프로필에 반영되어 다음 요청의 스냅샷에 포함된다.
- **달성 가치**: V1, V2
- **검증 방법**: 요청 1에서 배경 지식 발언 → 요청 2의 스냅샷에 해당 배경 지식과 출처(요청 1)가 포함되는지 확인

### AC2.6: 재요청 연결
- **설명**: 같은 학습자가 이전과 같거나 유사한 주제를 다시 요청하면,
  이전 설명이 `prior_explanation` 컨텍스트로 연결되고 그 설명의 이해 점수(있으면)와 사용 패턴이 함께 포함된다.
- **달성 가치**: V2, V1
- **검증 방법**: 주제 X 설명(점수 2) 후 주제 X 재요청 → 새 요청의 컨텍스트에 이전 설명·점수·패턴이 연결되는지 확인
