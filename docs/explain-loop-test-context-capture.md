# 테스트 문서 T2: 설명 요청·컨텍스트 수집

## 검증 대상 AC
- AC2.1: 요청 원문 보존 (PRD-2)
- AC2.2: 컨텍스트 출처 기록 (PRD-2)
- AC2.3: 학습자 스냅샷 고정 (PRD-2)
- AC2.4: 사용된 컨텍스트 표시 (PRD-2)
- AC2.5: 배경 지식 축적 (PRD-2)
- AC2.6: 재요청 연결 (PRD-2)

## 테스트 시나리오

### T2-S1: 원문 보존과 주제 분리
- **사전 조건**: 학습자 L1 등록
- **실행 단계**: 1) L1이 "음… OAuth에서 code 받고 나서 뭐하는 거임??  token이랑 뭐가 달라" 요청
  2) 설명 생성이 시작되기 직전 시점에 저장소에서 요청 조회
- **기대 결과**: `request_id`가 있고, `raw_text`가 공백·오타·물음표까지 입력과 동일, `topic`은 별도 필드(예: "OAuth 인가 코드와 토큰 교환")
- **검증 AC**: AC2.1

### T2-S2: 혼합 컨텍스트 출처
- **사전 조건**: L1과의 대화 3턴, 첨부 파일 `auth.ts`, 출처를 알 수 없는 붙여넣기 텍스트 1건
- **실행 단계**: 설명 요청 처리 후 `context_items` 조회
- **기대 결과**: 대화(`conversation`, 턴 번호), 파일(`code`, 경로), 붙여넣기(`source: unknown`) 모두 `kind`·`source`·`collected_at`이 채워짐
- **검증 AC**: AC2.2

### T2-S3: 스냅샷 불변
- **사전 조건**: L1 프로필 배경 지식 = ["HTTP 기본"]
- **실행 단계**: 1) 요청 R1 처리 2) L1 프로필에 "JWT 구조" 추가 3) R1의 `learner_snapshot` 조회
- **기대 결과**: R1 스냅샷의 배경 지식은 ["HTTP 기본"]만 있음
- **검증 AC**: AC2.3

### T2-S4: 사용 여부 표시
- **사전 조건**: 컨텍스트 5건이 수집되는 요청
- **실행 단계**: 1) 설명 생성 완료 2) 선택 기록의 `evidence`와 컨텍스트 `used` 값 대조
- **기대 결과**: `evidence`가 참조한 항목은 모두 `used: true`, 나머지는 `used: false`. 생성 완료 후 `used`가 비어 있는 항목 없음
- **검증 AC**: AC2.4

### T2-S5: 배경 지식이 다음 요청으로 이어짐
- **사전 조건**: L1 프로필 배경 지식 없음
- **실행 단계**: 1) 요청 R1에서 L1이 "나 백엔드 개발자고 SQL은 알아" 발언 2) 요청 R2 처리 3) R2 스냅샷 조회
- **기대 결과**: R1 컨텍스트에 `user_statement` 항목 존재, R2 스냅샷에 "백엔드 개발자", "SQL" 배경 지식이 출처(R1)와 함께 포함
- **검증 AC**: AC2.5

### T2-S6: 저점수 주제 재요청 연결
- **사전 조건**: L1이 주제 "OAuth 인가 코드 흐름" 설명 E1을 받고 점수 2 입력 (E1 사용 패턴: `level`, `structured-toc`)
- **실행 단계**: L1이 "아까 OAuth 그거 다시 설명해줘" 요청
- **기대 결과**: 새 요청의 컨텍스트에 `prior_explanation` 항목이 E1을 가리키며 점수 2와 사용 패턴 목록 포함
- **검증 AC**: AC2.6
